## 2. アーキテクチャ

```
MainActivity (Compose)
 └─ AppScreen … 権限チェック / ライフサイクル再開処理
     └─ ConversationScreen … 2カラムのメイン画面
PeerLinkManager … Nearby Connections ペアリング + 翻訳セッション調停 (Compose State保持)
VoiceSessionManager … Soniox 一時キー取得 → マイク16kHz PCM常時送信 → WS切断/失効の自動復旧
SonioxSocketClient … Soniox WebSocket (stt-rt-v5)
BackendClient … MTサーバーAPI (device_auth / temp_key)
```

- UI 状態(`state` / `peer` / `entries` / `translationPhase` / `online` / `started` など)は `PeerLinkManager` が `mutableStateOf` で保持し、Compose が直接購読する。
- 音声リスナーは OkHttp スレッドから呼ばれるため、UI 状態更新は必ず `onMainThread()` (mainHandler.post) 経由。**`mainHandler` より前に init でコールバック登録すると起動直後の NPE でクラッシュする**(過去事故済み・初期化順序を守ること)。

## 4. ペアリング(Nearby Connections)

- `Strategy.P2P_POINT_TO_POINT`、両端末が advertise+discover を同時実行し `onConnectionInitiated` で**自動 accept(操作ゼロ)**
- SERVICE_ID: `com.navypool.pairingtranslator.V1`。設定のペアリングキーが空でなければ `…V1-<key>` を使い、**同キー端末同士のみ発見**
- 同時 requestConnection の 8012(ENDPOINT_IO_ERROR) 回避: 端末名辞書順で小さい側だけが要求、他側は 4 秒フォールバック。要求は 3 回までバックオフ再試行
- HELLO 交換で互いの deviceId / 端末名 / model / 言語を通知
- ハートビート: 10 秒ごとに ping、25 秒無受信で強制切断→再探索
- スリープ復帰時(ON_RESUME)に advertise/discover を stop→500ms→start で張り直し(GMS が黙って止める対策)

### ワイヤプロトコル(BYTES ペイロード JSON, `connection/Protocol.kt`)
| type | フィールド | 用途 |
|---|---|---|
| `hello` | id, name, model, lang | 接続時の自己紹介 |
| `speech` | id, orig, trans, lang, ts | 自発話の確定結果送信 |
| `ping` / `pong` | ts | 生存確認 |
| `tcmd` | action("start"/"stop"), seq | 翻訳開始/停止のリモート指示 |
| `tack` | action, ok, seq, msg | tcmd の実行結果報告 |

## 5. 翻訳セッション(Soniox ボタン)

- **翻訳は自動開始しない**。ペアリングだけではグレー状態。ボタンタップでのみ開始
- ボタン表記は MT 準拠の英語: 停止中=`READY`(mic) / 開始処理中=`READY`(無効・3点ドットローディングアニメ) / 翻訳中=`LISTENING`(マイク波アニメ AVD `ic_mic_anime` + 淡い赤 `#FF4D4D`)
- アイコンは Compose painterResource ではアニメ再生されないため、`AndroidView`+ImageView で `(drawable as? Animatable)?.start()`(`AnimatedResIcon` ヘルパー)

### フェーズ遷移(`TranslationPhase`)
```
STOPPED → (タップ/相手のtcmd start) → STARTING
  自端末: キー取得 → Soniox WS 接続 (VoiceSessionManager)
  開始者は相手へ tcmd(start) を送信し tack を待つ
  両者の結果が揃い、両方 ok → RUNNING
  どちらか失敗 or 相手の応答タイムアウト → 両端末停止して STOPPED へロールバック
RUNNING → (タップ/相手のtcmd stop / 切断) → STOPPED
```
- **タイムアウト**: 相手の tack 猶予 30 秒、開始処理全体のハード上限 45 秒(`startWatchdog`)
- 二度押し防止: STARTING 中はボタン無効(`clickable(enabled=false)` + alpha 0.55)。MT と同様「セッション確定まで受け付けない」
- 未ペアリング時もボタンは無効(alpha 0.55)
- 設定画面を開いたときも `stopTranslation()`(=相手へ stop 通知)が走る(HS 準拠)

### VoiceSessionManager の動作
- `BackendClient.fetchTempKey(deviceId, duration 1〜60分)` → Soniox WS(`stt-rt-v5`)へ 16kHz PCM モノラル常時送信(VAD なし)
- **キー自動更新**: 有効時間の 5 分前(`KEY_REFRESH_MARGIN_MS`)にセッションを張り直し。キー失効切断は即再取得、それ以外の切断は 2 秒から指数バックオフ(上限 60 秒)で自動再接続
- `onPartial` でライブエントリ(認識中)を更新、`onFinal` で確定 → speech パケット送信
- エラー時は `VoiceState.ERROR` + メッセージをシステムエントリとして会話に追加

## 6. 設定画面(SettingsActivity)

| セクション | 内容 |
|---|---|
| ▼ 接続 | サーバーURL(MTサーバー、`poc_prefs.server_url` に保存・即時反映)、デフォルトに戻す。一時キー有効時間(1〜60分) |
| ▼ ペアリング | ペアリングキー表示 / 生成(8文字, 紛らわしい文字除外) / QR表示(560px ビットマップ) / スキャン(zxing, 縦固定キャプチャ)。キーは SERVICE_ID に反映(探索 OFF/ON で有効化) |
| ▼ デバイス | デバイスID(UUID, 管理画面の承認に使用) + コピー |
| ▼ デバッグ | 診断カード(端末名/APIレベル/アプリver/BT/Wi-Fi/NAN対応/GMS可否、BT OFF なら ON にするボタン) |
| 終了 | **アプリを終了**ボタン(赤・全幅) → `finishAffinity()` でタスク全体を閉じる |

- 設定画面はフルスクリーン(システムバー隠し・スワイプで一時表示)・ライト GMS ステータスバー
- メインから設定を開くと翻訳は強制停止(相手へも通知)

## 7. 権限
