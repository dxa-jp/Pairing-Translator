# アプリ仕様 — ペアリング翻訳

> 対象: D:\PairingTranslator (applicationId: `com.navypool.pairingtranslator`)
> 現行バージョン: v0.2.5 (versionCode 6) — 本書が最新のアプリ仕様であり、他の世代の仕様書は廃止済み。

## 1. 概要

2台のAndroid端末を**ユーザー操作なしで自動ペアリング**し、各端末が自分の音声を認識・翻訳して、**原文+訳文を相手端末へ送信・相互表示**する音声翻訳アプリ。テキストチャット機能は持たない(音声専用)。

- 音声認識・翻訳: Soniox クラウド API(WebSocket)
- 端末間通信: Nearby Connections API(オフラインP2P)
- 一時キーの供給: MultiTranslator サーバー(詳細は「サーバー仕様」「API仕様」参照)

## 2. 動作フロー(確定仕様)

```
(1) 起動 → サーバーへ端末登録 (POST /api/device_auth.php)
      ※管理UIでの承認が必要。未承認でも起動は続行し、ヘッダーに表示
(2) 近くのペア候補を自動検出 (advertise + discover 同時実行)
(3) 接続確立 → HELLO で互いの入力言語を交換
(4) POST /api/temp_key.php で Soniox 一時APIキー取得
(5) Soniox WS セッション開始(常時リスニング)
      自分の音声 → 自分の言語(固定)で認識 → 相手の言語へ翻訳
(6) 訳文が確定した時点で「原文+訳文」ペアを speech パケットで相手へ送信
      両端末が各自で同じことを行う(双方向)
```

**入力言語の扱い**: 両端末の言語をヒントとして言語を識別させ、厳格な言語強制は無効にする。受信トークンの言語・翻訳元言語・翻訳対象かを確認し、対象外を自分の吹き出しに入れない。日本語入力では、日本語文字のない原文も除外する。音声自体の誤認識や話者の取り違えを完全には防げない。

## 3. 画面構成

| 要素 | 内容 |
|---|---|
| ステータスヘッダー | 接続状態チップ(探索中/接続中/接続済み)+ 音声状態(🎧音声認識中など)+ サーバー状態(承認済み/未承認) + 言語ペア表示(自分 → 相手) |
| 入力言語ピッカー | 自分の入力言語を選択。約60言語。**変更は保存され、次回接続時から反映** |
| 診断パネル | 端末名/APIレベル/アプリバージョン/Bluetooth/Wi-Fi/NAN対応/GMS可用性。Bluetooth OFF時はON誘導ボタン |
| ログビューア | 接続・音声セッション・Soniox応答のダンプ(展開式) |
| 会話ビュー | 発話バブル。自分=右(原文が大+訳文が小)、相手=左(訳文が大+原文が小)。部分結果は「認識中…」表示でライブ更新 |

テキスト入力バーはない(音声専用)。

## 4. アーキテクチャ

```
AudioRecord (16kHz PCM s16le mono, 常時)
  → SonioxSocketClient (WSS, 一時キー認証, one_way翻訳)
      入力言語でフィルタし、発話終端で原文+訳文ペア確定(is_final トークンのみ蓄積)
  → PeerLinkManager (Nearby Connections 送受信 + 会話状態)
  → 会話ビュー表示 / speech パケット送信
```

### 4.1 ペアリング (PeerLinkManager)

| 項目 | 仕様 |
|---|---|
| Strategy | `P2P_POINT_TO_POINT` |
| Service ID | `com.example.droidautoconnection.SONIX_V1` |
| 自動accept | `onConnectionInitiated` で即 `acceptConnection`(UIなし) |
| 衝突回避 | 端末名の辞書順で小さい側のみ `requestConnection` を送信。相手から来ない場合は4秒後にフォールバック送信 |
| 再試行 | 接続要求は最大3回(1s/2sバックオフ)。advertise/discover開始失敗は最大5回(指数バックオフ) |
| 幽霊セッション対策 | start/resume時に stop→500ms待ち→start。8001/8002(既に実行中)は無視 |
| ハートビート | 10秒ごとにPING。25秒間無受信で強制切断→自動再探索 |
| 復帰処理 | ON_RESUME で advertise/discover を張り直し。CONNECTED中に通信途絶があれば破棄 |
| 画面 | 前面表示中はスリープしない (FLAG_KEEP_SCREEN_ON) |

### 4.2 音声セッション (VoiceSessionManager)

| 項目 | 仕様 |
|---|---|
| 開始タイミング | HELLO で相手言語を受信した時 |
| キー取得 | ペア確立後、`/api/temp_key.php` へ要求(実効1時間) |
| 録音 | AudioRecord, 16kHz/mono/PCM16, 常時送信(VADなし) |
| ローテーション | **55分ごと**にセッション張り直し(キー失効60分・Sonioxストリーム上限300分対策) |
| 停止 | 相手切断時はマイク+ソケット停止。再接続で自動再開 |
| エラー | キー取得拒否(未承認/クォータ超過)・Sonioxエラーは会話ビューにシステムメッセージ表示 |

### 4.3 翻訳確定ロジック (SonioxSocketClient)

- 原文と訳文は独立してストリーミングされ、**訳文は原文より遅れて届く**
- 入力言語と翻訳元言語を確認し、他言語の原文や訳文を混ぜない
- `<end>` または正常終了で「ファイナル原文 + ファイナル訳文」のペアをUIへ/相手へ送る
- 蓄積は `is_final` の立ったトークンのみ(未確定トークンを含めると断片化するため)
- 部分結果(partial)は発話全体のスナップショットとして置き換えて表示する
- ソケット切断時は未完了分を送信せず、途中表示を取り除く

## 5. 権限

| 権限 | 種別 | 用途 |
|---|---|---|
| RECORD_AUDIO | ランタイム | 音声認識 |
| BLUETOOTH_SCAN/ADVERTISE/CONNECT | ランタイム(API 31+) | 端末検出・接続 |
| NEARBY_WIFI_DEVICES | ランタイム(API 33+) | Wi-Fi系発見 |
| ACCESS_FINE_LOCATION | ランタイム(API 30以下のみ) | 旧BT発見 |
| ACCESS_WIFI_STATE / CHANGE_WIFI_STATE | install-time | Nearby接続のWi-Fi経路 |
| NFC / INTERNET / ACCESS_NETWORK_STATE | install-time(normal) | NFC経路抑止・Soniox/サーバー通信 |

## 6. 制約・注意

- 音声認識・翻訳には**インターネット接続必須**(端末間Nearby通信はオフラインで動く)
- 常時リスニングのため Soniox の**月次クォータ(USD/端末)を継続消費**する
- 同言語ペア(例: 両方日本語)は想定外
- 非GMS端末では動作しない。エミュレータ間ではNearby Connectionsが動かない
- MultiTranslator サーバー側は一切変更しない(本アプリから見て既存APIを利用するのみ)
