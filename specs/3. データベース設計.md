# ペアリング翻訳 データベース設計

> 本プロジェクトは **クライアント専用** のため、独自のサーバー DB を持たない。
> 永続化は (1) 端末ローカルの SharedPreferences、(2) サーバー側は MT (D:\MultiTranslator) の MariaDB を参照するのみ。

## 1. 端末ローカルデータ

### SharedPreferences: `poc_prefs`

| キー | 型 | 初期値 | 用途 |
|---|---|---|---|
| `device_id` | String(UUID) | 初回起動時生成 | サーバーへの端末登録/キー取得に使用。管理画面の承認キー |
| `my_lang` | String(言語コード, 例 `ja`) | 端末 locale から推定 | 自分の入力言語。HELLO で相手へ通知、Soniox の input に使用 |
| `pairing_key` | String(8文字, 空=なし) | 空 | ペアリングキー。空欄なら同アプリ全端末とペアリング可。SERVICE_ID(`com.navypool.pairingtranslator.V1-<key>`)に反映 |
| `server_url` | String(URL) | `https://multitranslator.dev.x-tools.biz/` | バックエンド API のベースURL(設定画面で変更可) |
| `temp_key_duration_minutes` | Int(1〜60) | 60 | Soniox 一時キーの有効時間(分)。キー発行時に送信 |

- 保存先: `SharedPreferences("poc_prefs", MODE_PRIVATE)`。暗号化なし(機微情報は含まない)
- マイグレーション: なし(キー追加のみの運用)

### インメモリ状態(永続化しない)

- 会話エントリ (`entries`: 最大 500 件、SpeechEntry = id/original/translation/mine/final/ts/isSystem)
- デバッグログ (`logs`: 最大 300 行)
- ペア状態 (`state` / `peer` / `translationPhase` / `online` / `started`)

## 2. サーバー側 DB(MT を参照)

テーブル設計のキャノンは **MT リポジトリ** および親 `D:\HonyakuSapo\specs\6. データベース仕様.md`(MariaDB `honyakusapo` / MT 用 vHost)。ペアリング翻訳が関わる範囲:

| 領域 | 内容 | 備考 |
|---|---|---|
| 端末レジストリ | device_id ごとの承認状態 | `device_auth.php` が参照。管理UIで承認/解除 |
| 使用量ログ | 端末ごとの Soniox 消費量(月次クォータ判定) | `QUOTA_EXCEEDED` 判定の元データ。管理UIのグラフ表示 |
| 一時キー発行履歴 | expires_at / expires_in_seconds / model | アプリは expires_at を診断表示に使うのみ |

- ログの保存形式(暗号化 `ENC1:` AES-256-GCM 等)は親リポジトリの仕様に従う。ペアリング翻訳自身はログを送信しない(MT の自動アップロード機能は移植していない)

## 3. 設計上の注意

- ペアリング翻訳で DB スキーマ変更が必要になった場合は **MT(または親)で先に変更** し、API 経由で利用する(ファミリー契約: 共通契約は親 specs がキャノン)
- クライアント側に SQLite / Room は未使用。会話履歴はプロセス終了で消える設計(必要になったら Room 導入を検討)
