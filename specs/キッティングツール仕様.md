# キッティングツール仕様 — ペアリング翻訳

> 対象: 端末の初期設定(キッティング) — 本書が最新のキッティング仕様であり、他の世代の仕様書は廃止済み。
> 現状は**手動キッティング手順**が正式運用。専用ツールは未実装(将来要件は第3章)。

## 1. 現行のキッティング手順(手動)

1台の端末を運用可能にするまでの標準手順。所要時間: 約5分/台。

### 1.1 配布物

| ファイル | 用途 |
|---|---|
| `ペアリング翻訳-vX.Y.Z-test.apk`(プロジェクトルート) | アプリ本体。debug署名。上書きインストール可 |

### 1.2 手順

1. **インストール**: APKを端末へ転送してインストール
   - USB接続時: `adb install -r ペアリング翻訳-v0.2.1-test.apk`
   - 旧「近接チャットPoC」/ 旧バージョンが入っていても上書きで可(別applicationId)
2. **起動して権限を許可**(初回のみ):
   - マイク(RECORD_AUDIO)
   - 近くのデバイス(BLUETOOTH系 + NEARBY_WIFI_DEVICES。Android 11以下は位置情報)
3. **入力言語を選択**: メイン画面のピッカーで自分の言語を設定
   - ペアの2台は**異なる言語**にすること(同言語ペアは想定外)
   - 変更は次回接続時から反映される
4. **サーバー登録と承認**:
   - 起動時に自動でサーバーへ登録される
   - ヘッダーに「未承認(管理UIで承認してください)」と出たら、MultiTranslator管理UI
     (https://multitranslator.dev.x-tools.biz/admin/) で当該端末を承認する
   - 承認後、アプリを前面に戻すと「承認済み」に変わる
5. **動作確認**:
   - ネットワーク(Wi-Fi/モバイル)接続を確認
   - ペア端末と近づけて自動接続 → 「接続済み・🎧音声認識中」になること
   - 話して、相手側に翻訳が表示されること
   - 詳細な確認項目は `TESTING.md` のチェックリストを使用

### 1.3 キッティング完了の判定基準

- [ ] ヘッダーが「サーバー: 承認済み」
- [ ] ペア接続が「接続済み」になり言語ペアが正しい表示(例: 自分: 🇯🇵 JP → 相手: 🇺🇸 US)
- [ ] 双方向で音声→翻訳表示が機能する
- [ ] 診断パネルで Bluetooth ON / Google Play Services 利用可能

## 2. トラブルシュート(キッティング時)

| 症状 | 対処 |
|---|---|
| 「未承認」が消えない | 管理UIでの承認漏れ。承認後にアプリを前面に戻す |
| 「QUOTA_EXCEEDED」 | 端末の月次クォータ超過。管理UIで上限変更または他端末を停止 |
| 「キー取得拒否」の他 | サーバー到達性(インターネット接続)を確認 |
| 接続されない | 両端末のBluetooth/Wi-Fi ON、同一Service IDのアプリバージョン、GMS搭載端末か確認 |
| 音声が翻訳されない | インターネット接続・言語ペアが異なること・診断パネルで🎧音声認識中か確認 |
