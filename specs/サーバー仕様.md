# サーバー仕様 — ペアリング翻訳(利用サーバー)

> 対象: ペアリング翻訳アプリが利用するバックエンドサーバー — 本書が最新のサーバー仕様であり、他の世代の仕様書は廃止済み。
> **重要: 本プロジェクト(DroidAutoConnetionSonix)からサーバーへは一切の変更を加えない。** 既存のMultiTranslatorサーバーを「そのまま利用」する。

## 1. サーバー概要

| 項目 | 値 |
|---|---|
| サーバー実体 | MultiTranslator プロジェクトのバックエンド(ローカル: D:\MultiTranslator) |
| URL | `https://multitranslator.dev.x-tools.biz/` |
| 管理UI | `https://multitranslator.dev.x-tools.biz/admin/` |
| ホスト | 152.70.111.153(SSH接続は後述) |
| スタック | PHP 8.3 (LiteSpeed/CyberPanel) + MariaDB、フレームワークなしの素PHP |
| APIのみの対応 | `/api/device_auth.php`(端末登録)、`/api/temp_key.php`(Soniox一時キー発行) |

詳細なリクエスト/レスポンス仕様は「**API仕様.md**」を参照。

## 2. アプリが利用するサーバー機能

1. **端末登録・承認**: アプリが自己登録 → 管理UIでオペレーターが承認(status=1)
2. **一時キー発行**: 承認済み端末へ Soniox 一時APIキーを発行(実効1時間、月次USDクォータで制限)

マスターキー(Soniox本キー)はサーバー側のみに保持され、アプリは一切保持しない。

## 3. データベース(参照系)

| テーブル | 用途 |
|---|---|
| `devices` | 端末登録。status=1が承認済み。月次コスト(USD)・クォータ管理 |
| `temp_key_history` | 一時キー発行履歴(管理UIの「履歴」で閲覧可) |
| `usage_logs` | Soniox利用ログ(cronで日次同期)。端末別コスト算出元 |
| `settings` | 同期カーソル等のサーバー設定 |

## 4. 運用(ペアリング翻訳の観点)

- **端末の承認**: 管理UIにログイン → デバイス管理で対象端末を承認。未承認の端末は一時キー取得に失敗し、アプリに「未承認」と表示される
- **クォータ管理**: 端末ごとの月次USD上限を管理UIで設定。超過端末は `QUOTA_EXCEEDED` となる
- **利用ログ**: 毎日03:00のcronでSoniox usage logsを同期(`fetch_usage_logs.php`)

## 5. 変更・デプロイに関する方針

- サーバーのファイル・DB・設定を本プロジェクトから変更することは**禁止**。調査(APIレスポンス確認など)のためのアクセスのみ許容
- サーバー側の不具合調査が必要な場合は管理UIの履歴(temp_key_history / usage_logs)を確認する
- SSH接続(管理オペレーション専用、本プロジェクトでは通常使用しない):
  - `Honyaku-Sapo`(ユーザー操作) / `Honyaku-Sapo_root-user`(root/DB操作) — `~/.ssh/config` に定義
- MultiTranslator本体の仕様詳細: D:\MultiTranslator\specs\ を参照(本プロジェクトでは複製しない)
